# 사용 설명서 — HFE Layout Simulator

명령창·코딩 없이 **exe 하나로** 검사 양식(A4)과 MES 화면 레이아웃을 설계하고, 인지공학(HFE)
규칙 58개로 자동 채점받는 방법을 설명한다.

## 1. 내려받기·실행

1. 브라우저에서 저장소 → 상단 **Actions** 탭
2. 초록 체크(✓)가 붙은 최신 **"Build Windows EXE"** 실행을 클릭
3. 페이지 맨 아래 **Artifacts → HfeLayoutSim-win64** 클릭 → zip 다운로드
4. **압축을 통째로 풀고** 그 안의 `HfeLayoutSim.exe` 더블클릭
   - Windows 보호 경고: **추가 정보 → 실행**
   - `rules` 폴더는 exe와 같은 폴더에 있어야 한다. (없어도 실행은 되지만 "내장 규칙으로
     진행할지" 묻는 창이 뜬다 — 이때 내장본은 배포 시점 규칙이라 사내 수정본과 다를 수 있다)

프로그램은 한 번에 하나만 뜬다(중복 실행 시 기존 창이 앞으로 나온다). 저장 위치·로그는
`%LOCALAPPDATA%\HfeLayoutSim\` 아래에 쌓인다.

## 2. 화면 구성

| 영역 | 내용 |
|---|---|
| 상단 툴바 | 새 양식/새 화면, 열기·저장, **카탈로그로 생성**, 실행취소/다시실행, **평가 실행(F5)**, HTML 내보내기 |
| 왼쪽 | 요소 팔레트(제목·라벨·입력란·체크박스·표·판정배지·버튼·서명란 등) + 배치 버튼 |
| 가운데 | 캔버스 — 구역 오버레이(POA/SFA/WFA/TA)와 여백·고정영역 가이드 토글 |
| 오른쪽 | **판정·지적 / 코칭 / 속성 / 강점** 4개 탭 |
| 맨 아래 | 상태 표시줄 — 현재 동작, 마지막 문제, 저장 상태 |

제목 표시줄에 **●** 가 붙어 있으면 저장하지 않은 변경이 있다는 뜻이다.

## 3. 기본 작업 흐름

1. **새 양식 (종이 A4)** 또는 **새 화면 (MES)** 클릭
2. 왼쪽 팔레트에서 요소를 고르고 **캔버스에 배치**(또는 더블클릭)
3. 캔버스에서 드래그로 이동, 방향키로 미세 이동(Shift+방향키는 크게 이동)
4. 배치할 때마다 **코칭** 탭이 갱신된다 — "이 위치는 적절 / 이 위치는 왜 부적절하고 어디로
   옮겨야 하는지 / 폰트·색상·크기·아이콘 권장값 / 순서를 이렇게 두면 생기는 오류 위험"
5. **속성** 탭에서 문구·좌표·크기·폰트·색·정렬·역할(Semantics)·판정 3중 코딩 등을 조정
6. **평가 실행(F5)** → **판정·지적** 탭에 PASS/FAIL 배너, 총점·등급, 카테고리 등급(A~F),
   지적 목록이 나온다
7. 지적을 클릭하면 캔버스가 해당 요소로 스크롤되고 3번 점멸한다
8. **HTML 리포트 내보내기…** 로 인쇄용 리포트를 저장

> 레이아웃을 편집하면 직전 평가 결과는 **무효(stale)** 로 표시되고 내보내기가 막힌다.
> 옛 판정을 최신 상태로 착각하지 않게 하기 위한 장치다 — 다시 F5를 누르면 풀린다.

## 4. 검사 내용을 직접 정의해서 양식 자동 생성

공정명·공정 순서·항목·기준·첨부 이미지·알람·서명자를 JSON으로 적어두면 8블록 표준을 지키는
레이아웃이 통째로 만들어진다. `catalog/incoming_inspection.catalog.json`을 복사해 고치면 된다.

```jsonc
{
  "processName": "수입검사 — Nitinol Wire",   // 검사 공정명
  "documentNo": "QC-IR-001",
  "identificationFields": ["품명", "LOT No.", "입고일"],
  "preconditions": [                            // 검사조건 게이트(검사 전 확인)
    { "text": "계측기 교정 유효기간 확인", "inputKind": "transcribe", "label": "계측기 관리번호" }
  ],
  "samplingNote": "KS Q ISO 2859-1, G-II, AQL 1.0",
  "steps": [                                    // 공정의 종류와 순서
    { "name": "치수 검사", "order": 1, "items": [
        { "name": "외경", "kind": "measure", "criterion": "1.20±0.05", "unit": "mm" },
        { "name": "인장강도", "kind": "measure", "criterion": "≥ 45", "unit": "N",
          "alarm": { "text": "규격 이탈 시 즉시 부적합 기록", "level": "warning" } },
        { "name": "그립 각도", "kind": "measure", "criterion": "35±2", "unit": "°",
          "image": "hook_angle_diagram.png" } ] },
    { "name": "외관 검사", "order": 2, "items": [
        { "name": "포장 라벨 LOT 일치", "kind": "check", "critical": true } ] }
  ],
  "alarms": [ { "text": "멸균 전 제품 — 장갑 착용", "level": "warning" } ],
  "signers": ["검사자", "승인자"]               // 2인 이상이어야 이원 서명 규칙 통과
}
```

- 항목 `kind`: `measure`(수치 측정 — `unit` 필수) / `check`(육안·가부) / `text`(서술 기입)
- 검사조건 게이트 `inputKind`: `check`(체크만) / `transcribe`(값을 옮겨 적기 — `label` 필요)
- `critical: true` → 안전 관련 항목이 되어 체크박스 대신 **전사 입력**으로 만들어지고
  (체크 습관화 방지), 해당 요소의 지적 심각도가 한 단계 올라간다
- `alarm.level`: `warning` → "주의:" 황색 박스 / `danger` → "경고:" 적색 굵은 박스 + 안전 관련 표시
  (그 외 값은 생성 시 오류로 거부된다)

툴바의 **카탈로그로 생성…** 에서 이 파일을 고르면 Paper/Screen 레이아웃이 바로 만들어진다.

## 5. 단축키

| 키 | 동작 |
|---|---|
| F5 | 평가 실행 |
| Ctrl+S / Ctrl+Shift+S | 저장 / 다른 이름으로 저장 |
| Ctrl+O | 열기 |
| Ctrl+Z / Ctrl+Y | 실행 취소 / 다시 실행 |
| Ctrl+D | 선택 요소 복제 |
| Delete | 선택 요소 삭제 |
| 방향키 / Shift+방향키 | 선택 요소 미세 이동 / 크게 이동 |
| Ctrl+`+` / Ctrl+`-` / Ctrl+0 / Ctrl+F | 확대 / 축소 / 100% / 화면 맞춤 |

## 6. 배치안 비교

여러 안을 각각 저장해두고 툴바 **배치안 비교…** 에서 2~3개를 고르면, 총점·카테고리 점수 표와
함께 **해소된 지적 / 새로 생긴 지적 / 그대로 남은 지적** 을 나눠 보여준다. 어떤 안을 채택할지
근거를 남길 때 쓴다.

## 7. 문제가 생겼을 때

| 증상 | 대처 |
|---|---|
| 창이 안 뜨고 "이미 실행 중" | 작업표시줄에서 기존 창을 찾는다 (중복 실행 방지 장치) |
| "파일을 읽을 수 없습니다" | 파일이 손상된 경우다. 안내에 나온 경로/줄 위치를 확인하고 백업본을 연다 |
| 비정상 종료 후 재실행 | "직전 작업을 복구할까요?" 창이 뜬다 — 30초마다 자동 저장된 내용이다 |
| 규칙 파일을 못 찾음 | `rules` 폴더를 exe 옆에 두거나, 내장 규칙으로 계속할지 선택한다 |
| 원인 모를 오류 | `%LOCALAPPDATA%\HfeLayoutSim\logs` 의 최신 로그 파일을 첨부해 문의한다 |

## 8. 채점 기준을 바꾸고 싶다면

모든 임계값·가중치·문구는 `rules/hfe_rules.json` 에 있다(코드에 숨겨진 수치는 없다).
수정 전후의 영향은 명령창을 쓸 수 있는 담당자가 `regress` 로 회귀 비교해 확인하는 것을
권장한다 — 절차는 `docs/RULE_COVERAGE.md` 참조.
