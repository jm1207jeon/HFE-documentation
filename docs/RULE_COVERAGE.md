## 갭 분석 결과 (2026-08-01)

체크리스트 15항목 중 13항목은 기존 51개 규칙으로 커버. 2건의 갭을 확인하고 규칙을 신설했다:

- **C7-07 서명 이원 구성** (Paper, Major, check=`signatureComposition`)
  — SignatureBox의 signerRole 기준 역할 구분 2인 미만이면 위반. 이중 확인(dual control) 통제.
- **C8-07 판정 선택지 완전성** (Both, Major, check=`judgmentOptions`)
  — FinalVerdict RadioGroup의 optionCount < 3이면 위반. 부적합·보류 경로를 막는 설계 방지.

→ 규칙 총 **53개**. 두 규칙 모두 evaluator·단위 테스트 포함.

## 규칙 튜닝 회귀 평가 절차

임계값을 조정할 때는 감(感)이 아니라 회귀 증거로 검토한다:

```bash
# 1. rules/hfe_rules.json을 복사해 임계값 수정 (예: C5-04 maxRun 4→5)
cp rules/hfe_rules.json /tmp/tuned.json && edit /tmp/tuned.json

# 2. 샘플 전체에 대해 기준 규칙 vs 수정 규칙 회귀 비교
dotnet run --project src/HfeLayoutSim.Cli -- regress /tmp/tuned.json samples/*.hfelayout.json
```

출력: 레이아웃별 총점/등급/PASS 변화 + **상태가 뒤집힌 규칙 목록**(위반↔통과, 지적 건수 변화).
변화가 의도한 범위인지 확인한 뒤에만 본 규칙 파일에 반영한다.
회귀 로직은 `HfeLayoutSim.Core.Tuning.RuleRegression`이며 단위 테스트로 고정되어 있다.
